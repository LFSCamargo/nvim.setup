# E2E test plan

This is the contract for `make e2e`. When runtime behavior changes, extend the matching case so the new path fails without the patch. The implementation is `scripts/e2e.sh` (fixture + fake CLIs) driving `scripts/e2e/e2e.lua` (child Neovim over RPC). Startup for that child is `scripts/e2e/e2e-init.lua`.

Run from the repository root: `make e2e` or `make test` (`check` then `e2e`).

## How it works

1. `scripts/e2e.sh` creates a temp dir with a Git repo, fake `codex` / `agent` / `gemini` / `claude` / `opencode` / `agy` binaries, and a wrapper probe.
2. It launches headless Neovim with `-l scripts/e2e/e2e.lua`.
3. The test file embeds a child Neovim (`--embed`), attaches a 120×40 UI, and drives mouse, keys, and Lua.
4. Fake CLIs record argv and stdin under `E2E_DIR`. The Git fixture has a modified file, a deleted file, untracked `.txt` / `.ts` / `.rs` files, and Devicons stubs for extension icons.

Do not talk to real Codex/Agent logins. Do not use the user's `~/.config/nvim`.

## Not covered here (do not pretend e2e proves them)

These need `make validate`, packaging docs, or a real editor session:

- Mason package install and Tree-sitter parser builds (`make validate`, `make tools`, `make parsers`)
- Real `codex` / `agent` / `gemini` / `claude` / `opencode` / `agy` login and streaming
- LSP, completion, format, and debug adapters against a real project
- Fugitive (`Space g s`) and gitsigns hunk maps
- nvim-tree default file-tree keys other than our Files/Git toggle
- Warp / terminal forwarding of Command+P
- Linux package-manager `make deps` branches

## Workspace and website checks

`node --test scripts/tests/workspace.test.mjs` checks that Nx and package scripts point to the shell tests in `scripts/shell/__tests__/`, that the moved tests resolve the repository root, that the Neovim E2E files exist, that Playwright points at `scripts/e2e/web-browser.spec.ts`, and that `apps/web/src/shared/` files live under `components/`, `hooks/`, `utils/`, or `constants/`. `pnpm test:workspace` runs this check plus the bootstrap, font, scan, format, and bump shell suites. The root `scripts/*.sh` commands are stable entry points for the implementations in `scripts/shell/`; this keeps `make install`, bootstrap, CI, and documented commands working after the folder move.

`pnpm --filter web test` typechecks the landing page and runs its Vitest visitor-path suite, including the on-site `/docs` reader, documentation and install code samples, Settings / Extensions / context-menu feature cards, the workspace / Git / Settings / Extensions / layout / AI agents screenshot tabs, header type contrast over the real backdrop (screenshot fills, install band), light/dark theme switchers, light-mode hero chrome (thin caret, dark screenshot rims), local-tool install docs on the install band, the screenshot lightbox chrome, unique home/docs titles with Open Graph and JSON-LD, and the infinite principles marquee (two equal halves, copies sized to the viewport). `pnpm test:web:e2e` runs the landing page's browser checks, screenshot lightbox, documentation sidebar, theme switching, nav type following the backdrop behind the glass (not a painted white/black shell), light-mode readability of the hero, feature cards, and docs, unique titles plus robots/sitemap for search engines, a documentation URL that still loads after refresh, and that the marquee track stays wider than the viewport with `animation-iteration-count: infinite`. `pnpm format:check` fails when Prettier or Tailwind class order is stale. GitHub Actions runs those format, typecheck, and build steps plus Semgrep; the visitor-path and Playwright suites stay on the machine. These are separate from the simulated Neovim UI suite.

# Settings, extensions, and command palette

The UI suite toggles icons from the Settings sidebar, checks persistence and reload, changes and resets indent width, checks the command palette mappings, opens and closes the Extensions sidebar, checks its marketplace heading and search field, installs a mocked Mason package from a result card, and verifies plugin ID validation and manifest add/remove.
